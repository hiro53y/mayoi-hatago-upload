# 仕様メモ（2.0）

検証時点: 2026-10-14 JST

## 目的

「不思議なダンジョンもどき」を、風来系（不思議のダンジョン系）の手応えを持つローグライクとして全面的に作り直す。名前・URL・PWA の id は1.0のまま。

## 権利方針

既存作品の固有名詞・キャラクター・敵名・アイテム名・地名・台詞・画像・音楽・効果音・ストーリーは使わない。ローグライク一般の仕組みだけを参考にし、名前と表現は独自にする。絵は1.0のGPT生成画像を使い、足りない分はコードで描き足した（SVG）。

## 主な数値

| 項目 | 値 |
|---|---|
| 地図 | 56×32、区画 3〜4 × 2〜3 |
| 視界 | 明るい部屋は全体、通路・暗闇は周り1マス、霧は周り2マス |
| プレイヤー | HP20・力8・満腹100で開始。レベルが上がるとHP+3〜6 |
| 満腹度 | 10ターンで1減る（腹持ちの印・お守りで半分）。0でHPが1ずつ減る |
| 命中 | プレイヤー95%、敵88%（見切りの印で−20%） |
| 打撃 | 攻撃力×（0.88〜1.12）×（k÷（k＋防御））。kはプレイヤー→敵20、敵→プレイヤー24 |
| 経験値 | レベルnに必要な合計 = 10×(n−1)^2.1 |
| 敵の出現 | 35〜65ターンごと。最大14体（店主・番人・仲間を除く） |
| 突風 | 同じ階に1,000ターンで予告、1,250ターンで次の階へ |
| 持ち物 | 20個（壺は1個）。倉庫60個、本編へ12個まで持ち込み |

## 終わり方

| 終わり方 | 持ち物 | 蓄え |
|---|---|---|
| 倒れる・あきらめる | すべて失う | 増えない |
| 帰還の巻物・踏破（本編・深層） | 倉庫へ（空きがある分） | 所持金を村の蓄えへ |
| 毎日の挑戦・道場 | 持ち帰らない | 増えない |

## 完成条件と確認方法

- `npm run test`：単体テスト・地図2,000通り・自動プレイの総当たり（例外と不変条件の違反が0）。
- `npm run build` が成功し、本番の JS に開発用の自動プレイ・確認用フックが入らない。
- スマホ縦画面（360〜400px幅）で、タイトル・村・冒険・持ち物・方向選び・店の支払い・結果が操作できる。


## v2.2 承認済み仕様（2026-10-15）

追加の基本画像30点を同じ画風の透過PNGに統一する。旧PNG21点と本編30階・深層99階、難易度、URL、PWA id/start_url/scopeを維持する。
未払いは壺の内容物まで再帰判定し、壺操作と倉庫預けを拒否する。矢は99本ごとに分け、満杯なら残りを床へ残す。
敵の段階表示は既定オン。通常敵かつ視界内のみⅠ～Ⅲを表示し、変装中・不可視・役割付きの人物とボスは除外する。
設定にJSONバックアップ／復元を追加。形式名・version=1・exportedAt・run・metaを格納し、確定前に要約を表示。10MBを超えるファイルと検証不合格の内容は拒否する。
既存キー fdm2:run / fdm2:meta を維持。tiers設定は旧セーブではtrueで補う。復元は fdm2:restore-journal に旧データを保全し、失敗／中断時に戻せる。壊れたデータは初期化・上書きしない。
終了処理はrun.completionIdとmeta.lastFinalizedで二重反映を防止し、村の保存完了後に途中データを削除する。

## v2.2.1 変更（2026-10-17、v2.2の保存UI仕様を撤回）
確認・復元・警告のUIを撤去する。自動保存・中断再開は維持し、保存成功を出発・終了の画面遷移条件にしない。終了時の二重反映防止は維持する。
読み込み自体は保存領域に書き込まない。省略された任意項目を補完する。読めない原文は上書き・削除前に `fdm2:preserved-before-v221:<元キー>` へ保全する。異なる原文は連番で保持し、保全できない場合は元キーを変更せずメモリー内で進行する。旧復元ジャーナルは読み込みを妨げず、上書き前に保全する。外部APIは追加しない。
